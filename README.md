# Семейный бюджет: ИИ-бот учёта расходов

Член семьи пишет боту в Telegram «кофе 350» — трата сохраняется: бот сам определяет сумму,
категорию и дату. Глава семьи видит и редактирует траты всех в веб-панели.

- **Telegram-бот с ИИ-агентом** — добавляет, показывает, считает, изменяет и удаляет траты
  по обычному тексту. Каждому доступны только его траты.
- **Веб-панель** — траты всей семьи: фильтры по члену семьи, периоду и категории, итоги
  с диаграммой, создание, редактирование, удаление. Работает через REST API.

Подробный дизайн и принятые решения — в [docs/design.md](docs/design.md).

## Быстрый старт

Нужен Docker с Compose.

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и скопируйте токен.
2. Получите ключ LLM. По умолчанию используется бесплатный тариф [Groq](https://console.groq.com/keys);
   подойдёт любой OpenAI-совместимый API (см. `.env.example`).
3. Создайте конфиг и впишите токен и ключ:
   ```bash
   cp .env.example .env
   ```
4. Запустите:
   ```bash
   docker compose up -d --build
   ```
5. Откройте панель http://localhost:8080, нажмите «Участники» и скопируйте ссылку-приглашение.
   Откройте её сами и отправьте членам семьи: нажав «Start», человек вступает в семью.
6. Напишите боту «кофе 350».

## Участники семьи

Бот отвечает только членам семьи. Вступают по ссылке-приглашению `t.me/<бот>?start=<код>`
из окна «Участники» в панели; посторонним бот предлагает попросить ссылку у главы семьи и
ничего о них не сохраняет. Сразу после вступления бот спрашивает, как подписывать человека
в семейном бюджете («Маша», «Мама»), — или оставляет имя из Telegram. Позже имя меняется фразой
«зови меня …». В том же окне панели участника можно переименовать, исключить (его траты остаются)
и обновить ссылку — старая перестанет работать.

Без `LLM_API_KEY` бот работает в упрощённом режиме: понимает только простые траты вида
«кофе 350», «такси 1200 вчера». Без `TELEGRAM_BOT_TOKEN` запускаются только панель и API.

## Что умеет бот

| Сообщение | Что произойдёт |
|---|---|
| «кофе 350», «такси 1200 вчера», «продукты 2500 и бензин 3000» | добавит траты |
| «сколько потратил на еду в этом месяце» | посчитает итог (считает база, не модель) |
| «покажи траты за неделю» | покажет список |
| «последнее было не 350, а 450» | исправит последнюю добавленную трату |
| «удали такси» | спросит подтверждение, удалит после «да» |

## Архитектура

```
Telegram ◄─ long polling ─► backend (Go): bot → agent → LLM
                                      │        └─ tools ─┐
Браузер ─► nginx (web) ─ /api ─► httpapi ─────► service ─► PostgreSQL
```

- **backend** — один Go-процесс: Telegram-бот (long polling, публичный адрес не нужен),
  ИИ-агент и REST API поверх общего сервисного слоя. Миграции применяются при старте.
- **web** — React + TypeScript + Mantine, раздаётся nginx, который проксирует `/api` на бэкенд.
- **postgres** — PostgreSQL 16.

### ИИ-агент

Агент работает через tool calling: `add_expenses`, `show_expenses`, `summarize_expenses`,
`find_expenses`, `update_expense`, `request_delete_expenses`.

- **Модель выбирает действие, ответ формирует сервер.** Подтверждения добавления и
  изменения, списки и итоги рендерит бэкенд. Это экономит запрос к LLM и исключает
  «галлюцинации» в цифрах и форматировании; свободный текст модель пишет только для уточнений.
- **Устойчивость к лимитам.** Бесплатные тарифы ограничены токенами в минуту для каждой модели
  отдельно, поэтому при 429 агент переключается на модели из `LLM_FALLBACK_MODELS`, а если
  ограничены все — ждёт столько, сколько просит провайдер (до 20 секунд). Служебный промпт
  написан по-английски: кириллица стоит примерно вдвое больше токенов.

- **Изоляция пользователей обеспечена кодом, а не промптом.** У инструментов нет параметра
  `user_id`: бэкенд подставляет Telegram ID отправителя, и каждый запрос к БД из бота
  ограничен `WHERE user_id = …`. Модель физически не может прочитать или изменить чужую трату.
- **Деньги — в копейках (`BIGINT`).** Суммы от модели разбираются из десятичной строки без float,
  итоги считает SQL.
- **Удаление подтверждается на сервере.** Инструмент только запоминает, что удалить, а ответ
  «да/нет» обрабатывается без LLM — модель не может удалить трату без согласия пользователя.
- **Даты.** В промпт передаются сегодняшняя дата, день недели и таймзона (`APP_TIMEZONE`),
  поэтому «вчера» и «в этом месяце» понимаются правильно.
- **Fallback.** Если LLM недоступна (сеть, лимиты), простые траты разбирает детерминированный парсер.
- Короткая память диалога (4 последних обмена, 30 минут) — для уточнений вроде «тот, что позавчера».

## REST API

Суммы — целые копейки, даты — `YYYY-MM-DD`.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/categories` | категории |
| `GET` | `/api/users` | члены семьи, включая исключённых (`is_member`) |
| `PATCH` | `/api/users/{id}` | переименовать: `{"name":"Мама"}`, пустое имя — вернуть имя из Telegram |
| `DELETE` | `/api/users/{id}/membership` | исключить из семьи |
| `GET` | `/api/invite` | ссылка-приглашение |
| `POST` | `/api/invite/rotate` | выпустить новую ссылку, старая перестаёт работать |
| `GET` | `/api/expenses?user_id=&category=&from=&to=&limit=&offset=` | список; `user_id` и `category` — через запятую |
| `GET` | `/api/expenses/summary?…` | итоги по категориям с теми же фильтрами |
| `POST` | `/api/expenses` | создать: `{"user_id","amount","category","spent_at","comment"}` |
| `GET` / `PUT` / `DELETE` | `/api/expenses/{id}` | получить / изменить / удалить |

## Конфигурация

Все параметры — в `.env` (пример с комментариями — `.env.example`):
`TELEGRAM_BOT_TOKEN`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_FALLBACK_MODELS`, `LLM_TIMEOUT`, `APP_TIMEZONE`,
`POSTGRES_*`, `WEB_PORT`.

## Разработка

```bash
cd backend && go test ./...
```

Интеграционные тесты репозитория запускаются на реальном PostgreSQL, если задан
`TEST_DATABASE_URL` (база очищается!).

Поговорить с агентом без Telegram (те же переменные окружения, что у сервера):

```bash
cd backend && go run ./cmd/chat -user 123
```

Панель локально: `cd web && npm install && npm run dev` — откроется на http://localhost:5173
с проксированием `/api` на `http://localhost:8081` (переменная `API_URL`).

## Решения и ограничения

- **Одна установка — одна семья**, как подразумевает ТЗ: панель без авторизации предназначена
  для домашней сети. Не выставляйте порт панели в интернет.
- Справочник `users` добавлен к модели из ТЗ: имена для панели и членство в семье.
  Код приглашения хранится в таблице `settings`.
- Память диалога и ожидающие подтверждения хранятся в памяти процесса и теряются при перезапуске.
- Бот понимает только текст.

## Как развивать дальше

- **Несколько семей в одном боте:** сущность «Семья» с владельцем и своей ссылкой-приглашением,
  вход в панель по одноразовому коду из бота.
- Голосовые сообщения через Whisper-совместимый API.
- Набор eval-фраз для автоматической проверки качества агента на разных моделях.
- Бюджеты по категориям с уведомлениями в бот.
