# Дизайн: сервис учёта семейных расходов

## 1. Модель развёртывания

**Одна установка — одна семья** (self-hosted)

- семья поднимает сервис через `docker compose up` и создаёт своего бота у @BotFather;
- члены семьи вступают по ссылке-приглашению `t.me/<бот>?start=<код>` из веб-панели;
  посторонним бот отвечает, что нужна ссылка, и ничего о них не хранит. Участника можно
  исключить, а ссылку — обновить;
- веб-панель открыта в локальной сети без авторизации; её пользователь — глава семьи.

Мультисемейный режим (сущность «Семья», приглашения, вход по коду) — вне рамок,
описан в README как направление развития.

## 2. Архитектура

```
Telegram ◄─ long polling ─► ┌──────────── backend (Go) ────────────┐
                            │ bot ──► agent ──► LLM (OpenAI-совм.) │
                            │  │        │ tools                    │
                            │  │        ▼                          │
Браузер ─► nginx (web) ─/api─► httpapi ─► service ─► postgres repo │
                            └──────────────────────┬───────────────┘
                                                   ▼
                                              PostgreSQL 16
```

- Бот и REST API живут в одном Go-процессе и используют общий сервисный слой.
- Long polling — не нужен публичный адрес и вебхук.
- nginx отдаёт собранную SPA и проксирует `/api/*` на бэкенд; наружу открыт один порт `8080`.

## 4. Модель данных

### `expenses` — сущность «Трата» из ТЗ

| Поле | Тип | Примечание |
|---|---|---|
| `id` | `BIGSERIAL PK` | |
| `user_id` | `BIGINT NOT NULL` → `users` | Telegram ID владельца |
| `amount` | `BIGINT NOT NULL CHECK (amount > 0)` | **в копейках**, никаких float |
| `category` | `expense_category` (enum) | см. ниже |
| `spent_at` | `DATE NOT NULL` | дата траты в таймзоне `APP_TIMEZONE` |
| `comment` | `TEXT NULL` | что купили: «кофе», «такси» — по нему бот ищет траты |
| `created_at`, `updated_at` | `TIMESTAMPTZ` | `updated_at` обновляется при изменении |

### `users` — справочник членов семьи

Вспомогательная таблица, чтобы панель показывала имена, а не числовые ID.
Заполняется автоматически при каждом сообщении боту.

| Поле | Тип |
|---|---|
| `telegram_id` | `BIGINT PK` |
| `username`, `first_name`, `last_name` | `TEXT` |
| `display_name` | `TEXT` — имя в семейном бюджете; пусто — имя из Telegram |
| `is_member` | `BOOLEAN` — состоит ли в семье |
| `joined_at` | `TIMESTAMPTZ` — когда вступил |
| `created_at`, `updated_at` | `TIMESTAMPTZ` |

### `settings` — ключ-значение

Сейчас хранит один ключ: `invite_code`, текущий код приглашения.

## 5. ИИ-агент

Цикл tool calling (до 6 шагов): сообщение пользователя → LLM вызывает инструменты →
результаты возвращаются модели → модель формулирует ответ.

### Инструменты

| Tool | Назначение |
|---|---|
| `add_expenses` | добавить одну или несколько трат («кофе 350 и такси 500») |
| `show_expenses` | показать пользователю список трат (ответ рендерит сервер) |
| `summarize_expenses` | итоги по категориям за период (ответ рендерит сервер) |
| `find_expenses` | найти траты с id перед изменением или удалением; пользователю не показывается |
| `update_expense` | изменить трату по `id` |
| `request_delete_expenses` | подготовить удаление — само удаление только после «да» |

### Принципы

- **Изоляция через архитектуру.** У инструментов нет параметра `user_id` — бэкенд
  подставляет его из Telegram-апдейта. Каждый запрос к БД из бота ограничен
  `WHERE user_id = $owner`. Модель не может обратиться к чужим тратам, что бы ей ни написали.
- **Деньги считает SQL, не модель.** Суммы приходят в рублях (`350`, `349.90`), бэкенд
  переводит их в копейки точным разбором строки; итоги считаются в БД.
- **Даты.** В системный промпт передаются сегодняшняя дата, день недели и таймзона —
  модель сама превращает «вчера», «на прошлой неделе» в конкретные даты `YYYY-MM-DD`.
- **Валидация на сервере.** Категория из enum, сумма > 0, корректная дата. Ошибка
  возвращается модели как результат инструмента, и она исправляется.
- **Подтверждение удаления — на сервере.** `request_delete_expenses` только запоминает
  ожидающее удаление и отдаёт его описание; бот спрашивает «Удалить …?». Следующее
  сообщение «да/нет» обрабатывается детерминированно, без LLM. Любое другое
  сообщение отменяет ожидание.
- **Короткая память диалога.** Последние 4 обмена (с вызовами инструментов), TTL 30 минут,
  в памяти процесса. Нужна для уточнений («да, вторую»).
- **Последовательная обработка.** Сообщения одного пользователя обрабатываются по очереди.
- **Ответы рендерит сервер.** После успешных `add`/`update`/`show`/`summarize` ответ собирается
  из данных, без второго запроса к модели: меньше токенов и никаких искажений в цифрах.
- **Лимиты провайдера.** При 429 — переключение на `LLM_FALLBACK_MODELS` (лимиты Groq считаются
  на модель), затем ожидание по подсказке провайдера, не дольше 20 секунд. Служебный промпт
  на английском: кириллица стоит примерно вдвое больше токенов.

### Fallback без LLM

Если LLM не настроена или недоступна (сеть, 429, 5xx), простые сообщения вида
«кофе 350», «такси 1200 вчера», «продукты 2500 12.10» разбираются детерминированным
парсером: сумма, дата (сегодня/вчера/позавчера/дд.мм[.гггг]), категория по словарю
ключевых слов. Остальное — вежливый ответ, что ИИ временно недоступен.

## 6. REST API

Суммы в API — целые копейки, даты — `YYYY-MM-DD`.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/categories` | список категорий |
| `GET` | `/api/users` | члены семьи, включая исключённых |
| `PATCH` | `/api/users/{id}` | переименовать участника |
| `DELETE` | `/api/users/{id}/membership` | исключить из семьи |
| `GET` | `/api/invite` | ссылка-приглашение |
| `POST` | `/api/invite/rotate` | новая ссылка вместо старой |
| `GET` | `/api/expenses` | список: `user_id`, `category`, `from`, `to`, `limit`, `offset` |
| `GET` | `/api/expenses/summary` | итоги по категориям с теми же фильтрами |
| `POST` | `/api/expenses` | создать |
| `GET` | `/api/expenses/{id}` | получить |
| `PUT` | `/api/expenses/{id}` | изменить |
| `DELETE` | `/api/expenses/{id}` | удалить |
| `GET` | `/healthz` | проверка живости |

Ошибки: `{"error": "текст"}` с кодами 400 / 404 / 500.

## 7. Веб-панель

Одна страница:

- фильтры: член семьи, период (пресеты + произвольный), категория; хранятся в URL;
- итоги: общая сумма за период и разбивка по категориям (кольцевая диаграмма);
- таблица трат с пагинацией; создание и редактирование в модальном окне, удаление с подтверждением.

## 8. Конфигурация (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен бота; без него запускается только API |
| `LLM_BASE_URL` | `https://api.groq.com/openai/v1` | OpenAI-совместимый эндпоинт |
| `LLM_API_KEY` | — | ключ; без него бот работает только через fallback |
| `LLM_MODEL` | `openai/gpt-oss-120b` | модель |
| `LLM_FALLBACK_MODELS` | `openai/gpt-oss-20b,qwen/qwen3.8-27b` | запасные модели при исчерпании лимита |
| `LLM_TIMEOUT` | `60s` | таймаут запроса к LLM |
| `APP_TIMEZONE` | `Europe/Moscow` | таймзона для «сегодня/вчера» |
| `POSTGRES_USER/PASSWORD/DB` | `budget` | доступ к БД |
| `WEB_PORT` | `8080` | порт панели на хосте |

## 9. Структура репозитория

```
backend/
  cmd/server/            точка входа
  internal/config/       загрузка конфигурации
  internal/domain/       сущности, категории, деньги
  internal/storage/      PostgreSQL-репозиторий и миграции
  internal/service/      бизнес-логика
  internal/httpapi/      REST API
  internal/agent/        ИИ-агент, инструменты, память, подтверждения
  internal/parser/       fallback-парсер
  internal/bot/          Telegram-бот
web/                     React-панель + nginx
docs/design.md
docker-compose.yml
.env.example
```
